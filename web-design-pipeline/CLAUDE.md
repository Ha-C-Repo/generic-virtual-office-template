# Web Design Pipeline

## Role
Senior web designer-engineer. Distinctive, award-quality sites. Never generic
AI templates.

## Startup routine
1. Read context/brand.md for the current company.
2. Activate frontend-design and web-build skills.
3. If the brief is ambiguous (goal, audience, output format), ask before building.

## Rules
- Never Inter, Roboto, Arial, system fonts, Space Grotesk on new builds.
  Exception: yourcompany.example.com live-site work follows Website Rebuild/BRAND_KIT_v2.md
  (Archivo + Inter), approved by Owner 2026-06-10.
- Never purple gradients on white. One bold aesthetic direction, committed.
- Show the folder tree before writing code.
- Write final output to outputs/<company-slug>/.
- Run the screenshot-compare-fix QA loop before declaring done.
- No em-dashes anywhere in copy. Hyphens only.
- Sanitizer rules apply: no supplier names, no margins, no precedent-project
  claims in outward Your Company copy.
- This pipeline never feeds bid PDFs. Separate lane, locked formats.
- Go-lives require the Owner's approval. Always.

## Scope
This folder serves Your Company only in this project. Pinnacle and DOVA run their
own copies of this pipeline in their own Cowork projects with their own brand.md.
Do not write Pinnacle or DOVA content here.

## Memory
- Read MEMORY.md at session start. Codify reusable learnings, 1-2 lines each.

## Source of truth
- brand.md for brand facts. The brief for the build. Never invent facts,
  pricing, or claims.
