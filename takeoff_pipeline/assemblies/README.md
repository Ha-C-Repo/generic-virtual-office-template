# Assembly Library v2

**Folder:** `takeoff_pipeline/assemblies/`
**Implements:** P10, P22, P29, F3, F4 (pattern text in `COWORK-HANDOFF-MASTER-2026-06-11.md`)
**Governed by:** `takeoff_pipeline/docs/TAKEOFF_SCHEMA_V2.md` sections 3.3, 3.4, 9, 10, 12.
Where a definition and that document disagree, the document wins.
**Applied by:** `takeoff_pipeline/apply_assemblies.py` (pipeline step 3 of schema section 13.1)

## Change control. Read this first.

Chat-session overrides of waste factors, labor hours, equipment time, or any
other definition value are PROHIBITED. These files are version controlled on
purpose: the takeoff stamp (schema 13.3, cell F1) records the git short hash
of this folder at apply time, so every BOQ and BOM is reproducible from the
TAKEOFF rows plus the committed definitions.

To change a value:

1. Edit the JSON file in a working copy.
2. Propose the change to Owner as a file diff.
3. Commit only after Owner approves.

`apply_assemblies.py` warns when this folder has uncommitted changes, because
stamping would then record a hash that does not describe the definitions
actually used. An AI session asked to "just bump the waste factor for this
bid" must refuse and propose a diff instead.

## No dollars. Ever. (P10, schema section 12)

Definitions carry quantities, hours, and time. Never a dollar value, never a
unit dollar figure, never anything the section 12 token scan would catch.
Loading a definition that contains a pricing token is a hard error in
`apply_assemblies.py`, and the VJ audit fails any definition embedding
pricing data. Pricing happens downstream in the locked estimate layer against
`bridge/bid_rates.py`, which is CEO-locked and pointed to, never copied.

## The four streams (P29)

Every definition carries four streams. One primary measured quantity drives
all of them:

| Stream | BOQ stream enum | Unit | Also lands on BOM |
|---|---|---|---|
| `materials` | `MATERIAL` | EA, LF, SF, LB, TON | Yes (BOM is what the shop orders) |
| `labor_hours` | `LABOR` | HR | No |
| `equipment_time` | `EQUIPMENT` | HR or MIN | No |
| `subcontract` | `SUBCONTRACT` | EA, LF, SF, LB, TON | No (scope context only) |

`subcontract` is nullable. All six shipped definitions carry `null` because
no subcontract scope is a safe default on every job; add scope per assembly
only with the Owner's approval.

Waste factors and rounding rules live INSIDE the definition, next to the
quantity they modify. Rounding is always UP, to the increment declared in the
definition (whole sheets, stick lengths, quarter hours, five-minute crane
blocks). Waste applies before rounding.

## Openings logic (F4, schema section 3.4)

Deck definitions declare `openings.deduct_threshold_sf`. For every deck AREA
row, `apply_assemblies.py` finds the OPENING child rows (notes token
`OPENING: <parent item_id>`) and:

- Openings OVER the threshold are DEDUCTED from the driving deck area AND
  generate framed-opening steel adds (perimeter frame angles, span headers)
  plus install labor, every row citing the OPENING row's item_id.
- Openings at or under the threshold are ignored (cut waste covers them) and
  counted in the run report, never silently.

This closes the classic double miss: deck overcounted because openings were
never deducted, AND frame steel undercounted because nobody added the angles
and headers. The geometry model is `square`: side = sqrt(opening SF),
perimeter = 4 x side, span = side. Good enough for framing adds; an opening
schedule with real dimensions beats it and belongs in the takeoff as manual
rows when available.

## Measured-class rule (schema section 9)

ANCH and PLATE are measured classes: their counts come from the column
schedule and typical details, and the measured TAKEOFF rows are the system of
record for ordering (P30). When measured rows of the class exist, an assembly
NEVER emits an order line for that class. It emits a BOQ cross-check row
instead (description starts `CROSS-CHECK ONLY`), and the validator compares
the assembly-derived count against the measured count, warning Ivan on
mismatch. This closes the anchor-rod double-count path: counted from the
column schedule AND generated by the column-base assembly.

When the takeoff has NO measured rows of the class, the assembly emits the
order line, flagged in notes for verification against the column schedule.

## Dual-mode scoping (schema section 3.3)

COUNT drives per-piece components and labor. LINEAR drives material weight.
Never both. A LINEAR row carrying the `GROUP: <count item_id>` token emits
only its `materials` stream; the COUNT anchor row's assembly drives the
labor and equipment. This closes the double count between a column assembly
and a stick-material assembly.

## Definition schema (ASSEMBLY_DEF_V2)

One JSON file per assembly. `assembly_id` must equal the file stem.

```
{
  "schema": "ASSEMBLY_DEF_V2",
  "assembly_id": "<file stem>",
  "description": "...",
  "provenance": "SEED <date> ...",
  "applies_to": {
    "item_class": "COL|BEAM|JST|DECK|PLATE|ANCH|MISC",
    "mode": "COUNT|LINEAR|AREA",
    "designation_includes": [],   // empty list = any designation in class+mode
    "designation_excludes": []
  },
  "openings": null | {
    "deduct_threshold_sf": <SF>,
    "geometry_model": "square",
    "framed_adds": [ { component_id, description, designation,
                       basis: "perimeter"|"span", pieces_per_opening,
                       unit: "LF", waste_factor, round, aisc } ],
    "labor_hours": [ { component_id, description, hours_per_opening, round } ]
  },
  "streams": {
    "materials": [ { component_id, description,
                     designation | designation_from_driver,
                     unit, qty_per_unit | per_sheet_sf,
                     waste_factor, round, cross_check_class,
                     length_lf, aisc } ],
    "labor_hours": [ { component_id, description, hours_per_unit, round } ],
    "equipment_time": [ { component_id, description, unit: "HR"|"MIN",
                          time_per_unit, round } ],
    "subcontract": null | [ { component_id, description, unit,
                              qty_per_unit, waste_factor, round } ]
  },
  "notes": "..."
}
```

Field notes:

- `qty_per_unit` multiplies the driver quantity (per EA, per LF, per SF).
  `per_sheet_sf` is the deck alternative: net SF divided by SF per sheet,
  rounded UP to whole sheets. Exactly one of the two per material component.
- `round` is always `{"direction": "up", "increment": <n>}`. Down or nearest
  is rejected at load: order quantities never round down.
- `cross_check_class` (nullable) marks a component as belonging to a measured
  class (ANCH or PLATE). See the measured-class rule above.
- `aisc: true` marks a component whose designation should resolve through
  `bridge/aisc_validator.py` (Hard Rule 5). `apply_assemblies.py` fills the
  BOM `lb_per_ft` input from the validator when it is importable, else leaves
  it blank for the operator and reports the skip. Weight cells are always
  formula cells, never typed constants.
- `designation_from_driver: true` carries the TAKEOFF row's designation onto
  the BOM order line (deck type, joist series, beam size). A definition never
  invents a member tag the drawings did not state.

## Seed values and calibration (F3)

Every quantity factor, labor hour, and equipment minute in the shipped
definitions is a SEED value, marked in `provenance`. They are starting points
pending calibration against PC7 shop actuals and the Owner's review. They are
NOT measured shop performance. Anyone pricing against a BOQ built from seed
factors must know that, which is why every output row's formula_ref names the
assembly and component that produced it.

## Shipped definitions

| File | Driver | Drives |
|---|---|---|
| `column_base.json` | COL COUNT (EA) | 4 anchor rods (cross-check), 1 base plate (cross-check), leveling and grout set, setting labor, crane minutes |
| `roof_deck_sf.json` | DECK AREA (SF, net of openings) | sheets, fasteners, install hours, crane time, framed-opening adds |
| `composite_deck_sf.json` | DECK AREA (SF, net of openings) | sheets, fasteners, install hours, crane time, framed-opening adds |
| `joist_each.json` | JST COUNT (EA) | joists (driver designation), erection hours, crane minutes |
| `beam_lf.json` | BEAM LINEAR (LF) | stick material with cut allowance, fab and erection hours, crane minutes |
| `stair_flight.json` | MISC COUNT (EA, designation contains STAIR) | stringers, treads, fab and erection hours, crane minutes |

Known gap, on purpose: a COL-class LINEAR row (column stick material) has no
definition yet and lands in the run report's unassigned list, loudly. Adding
`column_stick_lf` is a future diff for Owner, not a silent expansion here.
